El recorrido de un mensaje

RabbitMQ es una oficina de correos para aplicaciones. Una aplicación deja un mensaje (como una carta) y RabbitMQ se encarga de que llegue a quien tiene que leerlo, aunque quien lo envía no sepa quién es, ni si está disponible en ese momento. Mientras tanto, el mensaje espera guardado, sin perderse.

El viaje de un mensaje siempre es el mismo:

  1. El productor (quien envía) escribe un mensaje y le pone una etiqueta, la routing key.
  2. El mensaje llega a un exchange, que es el clasificador: mira la etiqueta y decide a qué buzones mandarlo.
  3. Las reglas que usa para decidirlo se llaman bindings: cada una une el exchange con un buzón.
  4. Los buzones se llaman colas. El mensaje espera en la cola, en orden, hasta que alguien lo recoja.
  5. Quien lo recoge es un consumidor. Cuando termina, responde a RabbitMQ con un acknowledgement (una confirmación) para decirle qué ha hecho con el mensaje.
  6. Si el consumidor lo rechaza y no se devuelve a la cola, el mensaje puede ir a una dead-letter queue, una cola especial para lo que no se pudo procesar.

Los tres tipos de exchange

No todos los exchanges reparten igual. El tipo decide cómo se comparan la routing key del mensaje y la del binding. Este laboratorio ofrece tres. Los ejemplos de estos diagramas usan el mismo mensaje, con la routing key pedido.pizza.

Direct: «solo si es exactamente igual»
En una frase

Entrega el mensaje a las colas cuyo binding tiene exactamente la misma routing key.

Ejemplo

Un pedido con pedido.pizza llega a la cola «cocina», cuyo binding es pedido.pizza. No llega a «barra», cuyo binding es pedido.bebida.

Cuándo usarlo

Cuando tienes categorías claras y cerradas: pizzas por un lado y bebidas por otro.

Fanout: «para todos»
En una frase

Entrega una copia del mensaje a todas las colas enlazadas, sin mirar la routing key.

Ejemplo

El aviso «cerramos en 10 minutos» llega a la cocina y a la barra a la vez, sea cual sea su etiqueta. Por eso, al crear un binding con un fanout, el laboratorio no te pide routing key.

Cuándo usarlo

Cuando quieres difundir lo mismo a todos: avisos, noticias, cambios de configuración.

Topic: «según un patrón»
En una frase

Entrega el mensaje a las colas cuyo binding tiene un patrón que encaja con la routing key. Las routing keys son palabras separadas por puntos.

Ejemplo

Los patrones usan dos comodines. * sustituye exactamente una palabra y # sustituye cero o más palabras. Así, pedido.* recibe pedido.pizza y pedido.bebida, y # recibe todo.

Cuándo usarlo

Cuando las etiquetas tienen niveles (pedido.pizza.grande) y cada cola quiere un grupo distinto: una solo las pizzas, otra todos los pedidos, otra solo lo urgente.

RabbitMQ tiene más tipos de exchange (por ejemplo, headers) y más tipos de cola, pero este laboratorio solo usa estos tres tipos de exchange y colas normales.
